# Recovery inspection: display and touch

Inspected an attached timelm in ADB Recovery. ESP `/dev/block/by-name/esp`
resolves to `/dev/block/sda29`; Windows `win` resolves to `/dev/block/sda30`.
`esd` is not present. Both filesystems were mounted read-only for inspection.
Private registry hives, logs and device captures are stored outside this repo.

## Display

Recovery advertises `1080x2460x60x72564cmd` and a 30 Hz variant for the selected
SW43103 PV command-mode DSC panel. The local known-booting image SHA256 is
`464aaa27cd2d2af35f7857c89cc6081aa7787b0dc3beb5af62dfe6b4c8b75a78`.

The Windows SYSTEM hive was copied with LOG1/LOG2, replayed into a separate
local file, then inspected without loading or changing the live OS registry.
Its GraphicsDrivers configuration contains both:

- `PrimSurfSize.cx/cy = 1080/2460`
- `ActiveSize.cx/cy = 1080/2460`, rotation 1 (identity)

The firmware DSC already uses 1080x2460, and Windows uses the basic display
path. There is no evidence to justify changing framebuffer dimensions. The
reported visual sizing may be DPI/OOBE layout; runtime display/DPI information
is the next check. No DPI or resolution registry overrides were applied.

## Touch

Installed third-party hardware packages are GPIO, SPMI and PMIC; oem3 is the
Microsoft Print to PDF package. No touchscreen or Qualcomm GPU package is
present. Replayed Windows ACPI enumeration and the DSDT extracted from the
current boot image have no I2C controller or touchscreen device.

The phone's Linux SW42902 driver is bound to i2c-2/address 0x28 and reports
firmware v0.74 / B3W68TIM. Reset/IRQ are TLMM 38/39 and VCL/VDD enables 67/68.

A Windows source candidate is now under
`GPLDrivers/Windows/Sw42902Touch`. It corrects the G8 packet layout and
dimensions, replaces the G8 initialization sequence and hardens the SPB path.
Host packet tests passed, including ASan/UBSan. Full KMDF compilation and
hardware validation remain pending; this is not an installable driver release.

The next required integration is a verified Kona I2C SPB host and ACPI resource
contract. The three existing Kona drivers cannot provide I2C by themselves.
Keep the working DSDT and framebuffer while that dependency is resolved.

## Reproducible checkout

Windows Git's `core.autocrlf=true` converted 111 overlay text files to CRLF,
causing `prepare_timelm.py` to reject the unchanged checkout's SHA256 manifest.
The new `.gitattributes` disables text conversion for the byte-verified timelm
overlay. The local overlay was restored to its original LF bytes and verified
against the existing manifest; no firmware asset content was changed.

## End-of-session limits

The initial decoder tests passed with ASan/UBSan. The final rerun after adding
invalid-Y/ID cases and clearing HID padding bits was blocked when drive C:
reported zero free bytes and WSL returned I/O errors. MSBuild/WDK is also absent.
Re-run the complete tests and compile the KMDF target after restoring space.
ADB changed to offline during the final checks. No new image was flashed and
no driver or registry changes were applied to the phone's Windows install.

Follow-up on 2026-10-19: Ubuntu-24.04 was moved using WSL's native `--manage
--move` operation to `D:\WSL\Ubuntu-24.04`. The default user and home data were
preserved; Linux read/write, Python and GCC checks passed. Swap now resides at
`D:\WSL\swap.vhdx`. The complete final SW42902 decoder tests were rerun with
ASan/UBSan and passed. WDK compilation and phone validation remain pending.
